КОНТЕКСТ ПРОЕКТА
Есть рабочий веб-прототип (приложены файлы: index.html, app.js,
config.js, schema.sql) — маркетплейс бьюти-услуг на Казахстан.
Backend уже готов и остаётся без изменений — Supabase (Postgres +
Auth + Storage), таблицы: profiles, master_profiles, salon_profiles,
vacancies, applications, messages, reviews, portfolio_photos, services,
salon_availability, bookings. Задача — не переписывать бэкенд, а
построить нативный SwiftUI-фронтенд поверх него через
Supabase Swift SDK (supabase-swift), сохранив всю бизнес-логику
(запись клиентов, отклики на вакансии, чат, бонусы, отзывы).

АУДИТОРИЯ И РЕЖИМЫ ПРИЛОЖЕНИЯ
Два режима, переключаемые пользователем (не два разных приложения):
1. Клиент — ищет и бронирует услуги (маникюр, барбершоп, косметология,
   массаж и т.д.)
2. Мастер/специалист — ищет вакансии, ведёт профиль/портфолио,
   переписывается с салонами, видит записи своих клиентов
(Роль салона может остаться в веб-кабинете — уточнить отдельно, если
нужна нативная версия и для салонов.)

СТРУКТУРА ЗАВЕДЕНИЙ (как у zapis.kz)
Город → Категория (Салоны красоты, Барбершопы, Ногтевой сервис,
Парикмахерские, Брови и ресницы, Косметология, Массаж и SPA,
Стоматология, Тату и пирсинг) → список мастеров/салонов → профиль →
запись.

ЭКРАНЫ И ФЛОУ (реализовать нативно на SwiftUI)

1. Главная (клиент)
   - Верх: выбор города + аватар профиля + колокольчик уведомлений
   - Search bar "Найди своего мастера"
   - Переключатель режима "Я клиент / Я мастер — ищу работу"
     (Segmented control или две вкладки)
   - Промо-герой с CTA "Найти"
   - Компактная пилюля баланса бонусов (тап → экран кошелька)
   - Карусель рекламных/промо-баннеров (с пометкой "Реклама" в углу,
     свайпаемая, TabView с PageTabViewStyle)
   - Сетка категорий (иконка в кружке + подпись), LazyVGrid,
     адаптивная: 4 колонки на iPhone, 6-8 на iPad
   - "Популярные мастера" — горизontальный ScrollView карточек

2. Поиск/список мастеров и салонов
   - Верхние фильтры-чипсы (Рядом / Сегодня / Цена / Ещё) —
     горизонтальный ScrollView
   - Карточка мастера/салона: фото, имя, специализация, рейтинг,
     расстояние, цена "от", слоты времени на сегодня (пилюли)
   - Бейдж типа заведения (Салон / Барбершоп / Частный мастер)
   - На iPad: список слева (NavigationSplitView), детали справа,
     вместо full-screen push как на iPhone

3. Флоу записи (4 шага, со степпером-индикатором прогресса)
   Мастер → Услуга и время (календарь недели + сетка слотов) →
   Подтверждение (услуга, дата/время, цена, комментарий) → Успех
   На iPad — можно показывать как модальный sheet form-sheet
   (.formSheet), не на весь экран

4. Режим "Я мастер — ищу работу"
   - Отдельный search bar "Найди вакансию"
   - Чипсы специализаций (Маникюр, Парикмахер, Барбер, Бровист,
     Косметолог, Массажист, Визажист, Администратор)
   - Фильтры: город, тип занятости, формат оплаты
   - Лента карточек вакансий → детальная страница → отклик/чат
   - Свой набор вкладок таб-бара в этом режиме: Вакансии / Отклики /
     Чат / Профиль

5. Beauty Feed — лента (LazyVGrid, 2 колонки на iPhone / 3-4 на iPad)

6. Магазин — табы категорий + сетка товаров + корзина

7. Бонусы и кошелёк — крупный баланс + история операций (List)

8. Профиль/кабинет мастера — портфолио (LazyVGrid фото), расписание,
   статистика, настройки

НАВИГАЦИЯ И АДАПТИВНОСТЬ (iPhone vs iPad) — ключевое требование
- iPhone: TabView с нижним таб-баром (5 вкладок), push-навигация
  через NavigationStack
- iPad: NavigationSplitView (сайдбар с разделами слева, список по
  центру, детали справа — трёхколоночный layout там, где уместно:
  например поиск мастеров), модальные экраны — form-sheet/popover,
  а не full screen cover
- Использовать size classes (horizontalSizeClass) для переключения
  между layout'ами, а не жёстко привязываться к устройству
- Поддержка Split View / Slide Over на iPad (multitasking)
- Landscape-ориентация на iPad обязательна, на iPhone — по желанию

ДИЗАЙН-СИСТЕМА (перенести в SwiftUI, ориентир — приложенный скриншот)
- Цвета как Color assets/токены: акцент розово-фуксиевый (~#E23B7A),
  фон светло-серый/белый, текст почти чёрный. Обязательно продумать
  и светлую, и тёмную тему (Dark Mode) — Apple это требует по HIG
- Шрифт: системный SF Pro с поддержкой Dynamic Type (никаких
  фиксированных размеров текста — только .font(.system(...)) с
  относительными стилями или кастомный шрифт через Font, тоже
  масштabируемый)
- Компоненты: скруглённые карточки (.cornerRadius 16-20, мягкая тень),
  пилюли для тегов/слотов, один явный CTA на экран
- Иконки: SF Symbols там, где подходят по смыслу (для консистentности
  и меньшего веса приложения), кастомные — только для брендовых вещей
  (категории услуг)
- Минимализм: много воздуха, не более одного акцентного цвета на
  экран, карточки без явных рамок — разделение через отступы и тень

ИНТЕГРАЦИИ И ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ
- Supabase Swift SDK: Auth (email/OTP), Database (Postgres queries/
  RLS уже настроены в schema.sql), Storage (фото профиля/портфолио),
  Realtime (для чата — в отличие от веб-версии, где чат не realtime,
  в приложении сделать через Supabase Realtime подписки)
- Push-уведомления (APNs): новая запись, отклик на вакансию,
  приглашение от салона, новое сообщение в чате
- Локализация: русский (основной), казахский (Localizable.strings,
  заложить архитектуру сразу под мультиязычность)
- Формат: тенге ₸, 24-часовой формат времени
- Соответствие Apple Human Interface Guidelines и App Store Review
  Guidelines

ВАЖНО ПРО ОПЛАТУ (App Store ограничения)
Депозит за запись и оплата услуг салона — это оплата реальной
физической услуги (не цифровой контент), поэтому по правилам Apple
её можно проводить через внешние платёжные методы (Kaspi Pay,
Freedom Pay, карта) без обязательного использования In-App Purchase.
In-App Purchase обязателен только для цифровых товаров/подписок
внутри приложения — например, если Premium-тариф для салона/мастера
покупается прямо в приложении, это, скорее всего, потребует IAP.
Уточнить у Apple Review Guidelines 3.1.1 на момент реализации и,
при сомнении, вынести оплату Premium на веб (оплата вне приложения)
либо реализовать через IAP — избежать отклонения при ревью.
